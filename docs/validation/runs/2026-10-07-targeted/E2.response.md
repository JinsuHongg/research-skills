**Both protocols can be valid.** The key is whether evaluation outcomes influence subsequent choices, and what population and adaptation setting the reported performance represents.

**Experiment 1: Nested evaluation**

- **Type / claim / hypothesis:** Confirmatory if prespecified; tests whether the complete inner-fold selection procedure improves performance over specified baselines.
- **Protocol and splits:** Tune hyperparameters exclusively within each outer training partition, using inner folds. Refit using that outer training partition, then evaluate once on its held-out outer fold. Fit preprocessing and any calibration within the corresponding training boundaries.
- **Leakage controls:** Outer-fold outcomes must not inform later choices among methods, settings, or procedures. “Untouched” must cover this feedback boundary, not just exclusion from training.
- **Baselines and ablations:** Give baselines comparable inner-fold tuning budgets and identical outer splits. Prespecify component ablations.
- **Metrics and analysis:** Specify primary and guardrail metrics, aggregation, seeds, repetitions, and stopping rules before evaluation. Report paired performance differences and uncertainty accounting for dependence across folds; do not treat fold scores as independent replicates.
- **Expected evidence / falsification:** Outer results estimate the performance of the selection procedure at the evaluated training sizes. A failure to meet a prespecified improvement criterion weakens the claim.
- **Unresolved:** Dataset provenance, preprocessing, split unit, metrics, comparison methods, compute budget, and failed-run policy are unspecified.

**Experiment 2: Unlabeled test-time adaptation**

- **Type / claim / hypothesis:** Confirmatory if the adaptation procedure is fixed beforehand; tests whether adaptation improves target performance under the specified access regime.
- **Protocol and splits:** Define whether adaptation accesses each input separately, a target batch, the entire target input set, or a sequential stream. Prespecify update steps, objective, parameters updated, stopping rule, ordering, and state resets. Keep target labels accessible only to the evaluator for scoring.
- **Leakage controls:** Using unlabeled evaluation inputs is **not inherently leakage** in this setting. However, target-label metrics must not guide adaptation settings, checkpoint selection, or later procedural choices. Those choices require separate development data.
- **Baselines and ablations:** Include the frozen, unadapted model; compare adaptation methods under comparable target-input access and tuning/compute policies. Ablate the claimed adaptation component.
- **Metrics and analysis:** Prespecify primary and guardrail metrics, paired effect estimates, uncertainty, seeds, and any batch/order repetitions. Account for shared adaptation state when defining independent evaluation units.
- **Expected evidence / falsification:** Results support performance of the specified adaptation procedure on the evaluated target setting. Failure to meet a prespecified improvement criterion, or unacceptable guardrail degradation, weakens the claim.
- **Unresolved:** Dataset provenance, adaptation access/state boundaries, metrics, statistical procedures, compute budget, and failure handling remain unspecified. The design alone cannot establish performance on unseen target domains.

For either protocol, if evaluation outcomes have already shaped later choices, classify the affected evidence as exploratory/development evidence. Disclosure does not restore independence; a fixed resulting procedure needs an untouched evaluation for independent confirmation.
